# MAX Chat · GREEN-API

Минимальный веб-интерфейс для отправки и получения текстовых сообщений в мессенджере **MAX** через [GREEN-API](https://green-api.com/max). Внешний вид — по мотивам [web.max.ru](https://web.max.ru/).

**Демо:** https://max-chat-seven.vercel.app

Стек: React 19, TypeScript, Vite. Без UI-библиотек и стейт-менеджеров.

## Что умеет

1. Вход по учётным данным инстанса GREEN-API (`apiUrl`, `idInstance`, `apiTokenInstance`). При входе проверяется, что инстанс авторизован (`getStateInstance`).
2. Создание чата по номеру телефона получателя (`checkAccount` → `chatId`).
3. Отправка текстовых сообщений (`sendMessage`) со статусами: отправляется → отправлено → доставлено → прочитано, повтор при ошибке.
4. Получение ответов через HTTP API (`receiveNotification` + `deleteNotification`) — сообщение собеседника появляется в чате без перезагрузки.

## Запуск локально

Нужен Node.js 20.19+ или 22.12+.

```bash
git clone https://github.com/jurmaev/max-chat.git
cd max-chat
npm install
npm run dev
```

Откройте http://localhost:5173.

Сборка продакшн-версии: `npm run build`, результат в `dist/`. Проверить сборку локально: `npm run preview`.

## Подготовка инстанса GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com) и создайте инстанс для MAX (тариф «Разработчик» бесплатный).
2. Авторизуйте инстанс: отсканируйте QR-код в приложении MAX.
3. Скопируйте `apiUrl`, `idInstance` и `apiTokenInstance` со страницы инстанса.
4. В настройках инстанса оставьте поле **webhookUrl пустым** и включите получение уведомлений о входящих сообщениях и статусах. Если указан внешний webhook, очередь HTTP API не наполняется и ответы в интерфейс не придут.

## Как проверить сценарий из задания

1. Войдите с данными инстанса.
2. Введите номер получателя (например, `79991234567`) и нажмите «+».
3. Напишите сообщение и нажмите Enter (Shift+Enter — перенос строки).
4. Ответьте на сообщение с телефона получателя в MAX — ответ появится в чате.

## Устройство

```
src/
├── api/
│   ├── greenApi.ts        клиент GREEN-API: формирование URL, разбор ошибок
│   └── types.ts           типы запросов и уведомлений
├── model/
│   ├── chatReducer.ts     состояние чатов и сообщений (useReducer)
│   ├── notifications.ts   уведомление GREEN-API → событие чата
│   └── types.ts           Chat, Message
├── hooks/
│   └── useNotifications.ts  цикл long polling входящих уведомлений
├── components/            LoginScreen, Sidebar, ChatWindow, Composer, …
└── utils/                 телефоны, даты, localStorage
```

Решения, которые стоит отметить:

- **Адресация по chatId.** В MAX сообщения отправляются по `chatId`, а во входящих уведомлениях собеседник тоже определяется по `chatId`. Поэтому новый чат создаётся через `checkAccount`, а не подстановкой `номер@c.us`.
- **Надёжное получение.** Уведомление удаляется из очереди только после обработки. Если связь оборвалась между получением и удалением, уведомление придёт повторно, а редьюсер отбросит дубль по `idMessage`. При ошибках сети цикл делает паузу с экспоненциальным ростом (до 30 с) и показывает баннер.
- **Отмена запросов.** Long polling идёт через `AbortController`: при выходе или смене инстанса висящий запрос отменяется, двойного цикла в StrictMode не возникает.
- **Оптимистичная отправка.** Сообщение сразу появляется в ленте с локальным id, после ответа API id заменяется на `idMessage`, дальше статусы приходят уведомлениями `outgoingMessageStatus`. Статусы только растут: запоздавшее «доставлено» не откатит «прочитано».
- **Сообщения с телефона.** Сообщения, отправленные из самого приложения MAX (`outgoingMessageReceived`), тоже появляются в ленте.
- **Сохранение между перезагрузками.** Учётные данные и история хранятся в `localStorage` (история — отдельно для каждого инстанса). Сообщения, отправка которых прервалась перезагрузкой, помечаются как неотправленные с кнопкой «Повторить». Кнопка «Выйти» удаляет учётные данные.

## Ограничения

- Только текстовые сообщения — по условию задания. Остальные типы уведомлений пропускаются.
- Новый чат можно создать только по номеру с кодом 7 или 375: `checkAccount` в MAX поддерживает только их.
- Токен инстанса хранится в `localStorage` браузера, а запросы идут к GREEN-API напрямую из браузера. Для демо это приемлемо; в продакшене запросы стоит проксировать через бэкенд, чтобы токен не попадал на клиент.
- История живёт только в браузере: GREEN-API не отдаёт в этом сценарии старую переписку.

## Деплой

Проект — статический SPA. Проще всего задеплоить на Vercel или Netlify: импортировать репозиторий, команда сборки `npm run build`, папка `dist`. Для GitHub Pages укажите `base: '/<имя-репозитория>/'` в `vite.config.ts`.
